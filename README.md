# A & H — наше пространство

Приватное веб-приложение для двоих: воспоминания, дневник, желания и планы.
Устанавливается на iPhone через Safari как обычное приложение.

## Что нужно сделать один раз

### 1. Создать проект в Supabase

1. https://supabase.com → Start your project → войти через GitHub.
2. New project. Пароль базы данных сохраните — восстановить его нельзя.
3. Дождаться, пока проект создастся (~2 минуты).

### 2. Отключить публичную регистрацию

Supabase → **Authentication → Providers → Email** → выключить **Enable Sign Ups** → Save.

Это главный шаг приватности: после него завести аккаунт может только владелец
проекта вручную, из панели.

### 3. Создать два аккаунта

Supabase → **Authentication → Users → Add user → Create new user**.
Два раза: себе и второй половинке. **Auto Confirm User — включить.**

### 4. Применить схему базы данных

Supabase → **SQL Editor → New query** → вставить целиком содержимое
`supabase/migrations/0001_initial_schema.sql` → **Run**.

Скрипт создаёт таблицы, включает Row Level Security, заводит приватное
хранилище фотографий и профили для уже созданных пользователей.
Запускать повторно безопасно.

### 5. Подставить ключи

Скопировать `.env.example` в `.env.local` и заполнить значениями из
Supabase → **Settings → API**:

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...
```

`.env.local` в `.gitignore` и в репозиторий не попадает.

### 6. Подключить хранилище файлов (Cloudflare R2)

Фотографии и видео лежат не в Supabase, а в Cloudflare R2 — там 10 ГБ
бесплатно и не тарифицируется трафик. Подробности в разделе
«Принятые решения» ниже.

1. https://dash.cloudflare.com → зарегистрироваться → **R2**.
2. **Create bucket**, имя `our-space-media`, расположение **Europe**.
3. Бакет оставить **приватным** — файлы отдаются только по временным ссылкам.
4. **Manage API Tokens → Create API Token**, права **Object Read & Write**,
   область — только этот бакет. Сохранить Access Key ID и Secret Access Key.
5. В настройках бакета → **CORS Policy** вставить:

```json
[
  {
    "AllowedOrigins": ["https://ваш-адрес.vercel.app", "http://localhost:3000"],
    "AllowedMethods": ["GET", "PUT"],
    "AllowedHeaders": ["content-type"],
    "ExposeHeaders": ["etag"],
    "MaxAgeSeconds": 3600
  }
]
```

Без этого браузер откажется загружать файлы напрямую в хранилище.

6. Дописать четыре значения в `.env.local` (см. `.env.example`).

### 7. Применить вторую миграцию

SQL Editor → вставить `supabase/migrations/0002_media_and_video.sql` → Run.
Добавляет поля для видео и обложек.

## Запуск

```bash
npm run dev
```

Открыть http://localhost:3000

## Как устроен проект

```
src/
  app/
    (auth)/login/       вход; Server Actions вместо клиентского JS
    (app)/              всё, что за паролем — общий layout с нижней навигацией
      page.tsx          главная: счётчик отношений
      memories/         фотографии
      diary/            дневник
      wishlist/         желания
      plans/            планы
      settings/         настройки и выход
    auth/callback/      возврат по ссылке из письма Supabase
    offline/            заглушка без интернета
    manifest.ts         манифест PWA
  components/           UI, разбитый по разделам
  config/app.ts         название, имена, цвета — всё меняется здесь
  lib/supabase/         клиенты для браузера и сервера
  lib/data/             запросы к базе
  types/database.ts     типы таблиц (держать в паре с SQL-схемой)
  proxy.ts              проверка сессии перед каждым запросом
public/sw.js            service worker
supabase/migrations/    SQL-схема
```

## Принятые решения

**Почему нет публичной регистрации.** Пространство рассчитано ровно на два
аккаунта. Любой авторизованный пользователь — это один из двоих, поэтому
политики доступа строятся вокруг функции `is_member()`.

**Что видит каждый.** Фотографии, дневник, желания и планы общие — в этом смысл
приложения. Редактировать и удалять запись может только её автор. Запись
дневника с установленной датой открытия физически не отдаётся второму человеку
до наступления срока: это проверка в RLS-политике, а не скрытие в интерфейсе.

**Почему service worker написан вручную.** Next.js 16 собирается Turbopack,
а `@serwist/next` работает только с webpack — сборка бы падала.

**Почему в кэш не попадают страницы с личными данными.** Иначе фотографии и
записи оставались бы доступны на устройстве после выхода из аккаунта.
Офлайн кэшируется только оболочка приложения и страница-заглушка.

**Почему фотографии не проходят через `next/image`.** Ссылки на файлы
подписанные и живут час, поэтому оптимизатор каждый раз считал бы их новыми.
Изображения сжимаются на устройстве при загрузке — до 1.6 МБ и 2400px.

**Почему файлы в Cloudflare R2, а не в Supabase Storage.** У Supabase на
бесплатном тарифе 1 ГБ хранилища и 5 ГБ трафика в месяц, а каждый просмотр
видео — это скачивание файла заново. У R2 10 ГБ бесплатно и трафик не
тарифицируется вообще; сверх лимита — $0.015 за ГБ против $25/мес за
Supabase Pro. База, авторизация и все таблицы остались в Supabase.

**Почему файлы не проходят через наш сервер.** Браузер получает временную
ссылку и заливает файл прямо в R2. Иначе видео упёрлось бы в ограничение
Vercel на размер тела запроса (4.5 МБ).

**Почему `src/lib/media/shared.ts` отделён от `src/lib/data/photos.ts`.**
Ключи от R2 — настоящие секреты. Файлы, которые их касаются, помечены
`server-only`, поэтому всё, что нужно и браузеру тоже, вынесено отдельно.
Импорт из общего модуля не тянет за собой серверный код.

## Проверка на iPhone

Service worker требует HTTPS. С `localhost` он работает, но по локальной сети
на телефоне — нет. Установку на домашний экран проверять только на адресе
Vercel, а не на домашнем Wi-Fi.
