# Запуск копии «Our Space» с нуля

Это копия кода. Внутри нет ни одного ключа от старого сайта — все сервисы
регистрируем заново. Идём строго по шагам, ничего не пропуская.
Каждый шаг заканчивается проверкой «как понять, что получилось».

Всё, что нужно, — бесплатно.

---

## Шаг 0. Решить, на чей аккаунт всё регистрировать

Понадобятся 4 аккаунта: **GitHub**, **Supabase**, **Cloudflare**, **Vercel**.

- Если сайт останется под твоим присмотром — регистрируй на себя.
- Если человек будет им владеть сам — заводите аккаунты на его почту, а он
  потом добавит тебя в проект.

**Важно:** аккаунты старого сайта не переиспользуем. Новый Supabase, новая
корзина в Cloudflare, новый репозиторий, новый проект Vercel. Иначе два сайта
будут смотреть в одну базу и видеть чужие фотографии.

## Шаг 1. Установить зависимости

Открой терминал в этой папке и выполни:

```bash
npm install
```

Это скачает библиотеки (папка `node_modules`, ~1 ГБ). Занимает 1–3 минуты.

**Проверка:** появилась папка `node_modules`, в конце нет красных строк `ERR!`.

---

## Шаг 2. Создать проект в Supabase (база данных и вход)

1. Открой https://supabase.com → **Start your project** → войти через GitHub.
2. **New project**.
   - Name: любое, например `our-space-2`.
   - Database Password: нажми Generate и **сохрани его в заметки** —
     восстановить нельзя.
   - Region: **Frankfurt (eu-central-1)**. Не выбирай Азию, даже если Supabase
     её советует: интернет из Ташкента идёт в Азию через Европу, и сайт станет
     заметно медленнее (проверено: Франкфурт 178 мс, Сеул 434 мс).
3. Подожди ~2 минуты, пока проект создастся.

**Проверка:** проект открылся, слева видно меню Table Editor / SQL Editor.

---

## Шаг 3. Закрыть регистрацию и завести двоих пользователей

Это главный шаг приватности: сайт только для двоих, посторонний не сможет
создать себе аккаунт.

1. **Authentication → Sign In / Providers → Email** → выключить
   **Allow new users to sign up** → **Save**.
2. **Authentication → Users → Add user → Create new user**.
   - Email и пароль первого человека.
   - **Auto Confirm User — включить** (иначе он не сможет войти без письма).
   - Повторить для второго человека.

**Проверка:** в списке Users ровно две строки, у обеих статус подтверждён.

---

## Шаг 4. Создать таблицы и подставить ключи Supabase

1. **SQL Editor → New query**.
2. Открой в этой папке файл `supabase/setup-all.sql`, скопируй **всё
   содержимое целиком** и вставь в редактор → **Run**.
   Это вся схема сайта сразу (профили, фото, дневник, чат, игры, календарь).
   Выполняется несколько секунд.
3. Теперь ключи. Скопируй два значения в файл `.env.local` в этой папке:
   - `NEXT_PUBLIC_SUPABASE_URL` — **Project Settings → Data API → Project URL**,
     адрес вида `https://xxxxxxxx.supabase.co` — **и больше ничего**.
     Если скопировался хвост `/rest/v1/` — его надо убрать: с ним вход
     отваливается с непонятным «Неверная почта или пароль».
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY` — **Project Settings → API Keys**,
     публичный ключ. В новых проектах он называется **Publishable key** и
     начинается с `sb_publishable_`; в старых — **anon public** и начинается
     с `eyJ`. Годится любой из них, лишь бы не Secret / service_role.

Публичный ключ виден в браузере — это нормально и не опасно: доступ к данным
закрыт политиками Row Level Security, а не секретностью ключа.

**Проверка:** внизу SQL Editor написано `Success`. В **Table Editor** видны
таблицы `profiles`, `photos`, `diary_entries`, `wishes` и другие. В таблице
`profiles` уже две строки — по одной на каждого пользователя.

## Шаг 5. Хранилище для фото и видео (Cloudflare R2)

Фотографии лежат не в Supabase, а в Cloudflare R2: там 10 ГБ бесплатно и не
берут денег за скачивание.

1. https://dash.cloudflare.com → зарегистрироваться → в меню слева **R2**.
   Cloudflare попросит привязать карту даже для бесплатного тарифа —
   без превышения 10 ГБ списаний не будет.
2. **Create bucket**:
   - имя, например `our-space-2-media` (своё, не такое, как у старого сайта);
   - Location: **Europe (EU)**;
   - остальное по умолчанию, бакет **остаётся приватным** — файлы отдаются
     только по временным ссылкам, которые генерирует сайт.
3. **R2 → API → Manage API Tokens → Create API Token**:
   - Permissions: **Object Read & Write**;
   - Specify bucket: только что созданный бакет;
   - **Create**. Покажут два значения — **Access Key ID** и
     **Secret Access Key**. Secret показывают ровно один раз, скопируй сразу.
4. Впиши в `.env.local`:
   - `R2_ACCOUNT_ID` — Account ID, его видно в правой колонке страницы R2
     (он же в адресе `https://ЭТА_ЧАСТЬ.r2.cloudflarestorage.com`);
   - `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` — из пункта 3;
   - `R2_BUCKET` — имя бакета.
5. Бакет → вкладка **Settings → CORS Policy → Edit** → вставить:

```json
[
  {
    "AllowedOrigins": ["http://localhost:3000"],
    "AllowedMethods": ["GET", "PUT"],
    "AllowedHeaders": ["content-type"],
    "ExposeHeaders": ["etag"],
    "MaxAgeSeconds": 3600
  }
]
```

Боевой адрес сайта добавим сюда же на Шаге 10, когда он появится.

**Без CORS браузер молча блокирует загрузку**, а на сайте это выглядит как
«нет связи с хранилищем» — не пропускай этот пункт.

Эти три ключа — **настоящие секреты**, полный доступ к файлам. Никому не
пересылать, в GitHub не класть (файл `.env.local` уже в `.gitignore`).

**Проверка:** в `.env.local` заполнены все четыре строки `R2_*`.

## Шаг 6. Ключи для push-уведомлений

В терминале в этой папке:

```bash
npx web-push generate-vapid-keys
```

Ответит двумя строками — Public Key и Private Key. Перенеси их в `.env.local`:

- `NEXT_PUBLIC_VAPID_PUBLIC_KEY` — Public Key
- `VAPID_PRIVATE_KEY` — Private Key

**Проверка:** обе строки заполнены длинными наборами символов.

## Шаг 9. Выложить сайт на Vercel

1. https://vercel.com → войти через GitHub → **Add New → Project** → выбрать
   репозиторий → **Import**.
2. Framework Next.js определится сам. Ничего не меняй, кроме переменных.
3. Раскрой **Environment Variables** и добавь по одной:

| Имя | Откуда взять |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | из `.env.local` |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | из `.env.local` |
| `R2_ACCOUNT_ID` | из `.env.local` |
| `R2_ACCESS_KEY_ID` | из `.env.local` |
| `R2_SECRET_ACCESS_KEY` | из `.env.local` |
| `R2_BUCKET` | из `.env.local` |
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY` | из `.env.local` |
| `VAPID_PRIVATE_KEY` | из `.env.local` |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase → Project Settings → API Keys → **service_role** (секрет!) |
| `CRON_SECRET` | придумай длинную случайную строку, например 32 символа |

4. **Deploy**. Через 1–2 минуты получишь адрес вида
   `https://our-space-2-xxxx.vercel.app` — запиши его.

Регион серверов (Франкфурт) уже прописан в `vercel.json`, менять не нужно.
Последние две переменные нужны ежедневной задаче `/api/cron/daily` —
без них сайт работает, но не будет утренней рассылки.

**Проверка:** деплой зелёный, адрес открывается, показывается экран входа.

## Шаг 10. Связать боевой адрес с Supabase и Cloudflare

Пока этого нет, на боевом сайте не будут работать вход и загрузка фото.

1. **Cloudflare R2** → бакет → Settings → CORS Policy → допиши боевой адрес:

```json
[
  {
    "AllowedOrigins": ["https://ТВОЙ-АДРЕС.vercel.app", "http://localhost:3000"],
    "AllowedMethods": ["GET", "PUT"],
    "AllowedHeaders": ["content-type"],
    "ExposeHeaders": ["etag"],
    "MaxAgeSeconds": 3600
  }
]
```

2. **Supabase → Authentication → URL Configuration**:
   - **Site URL**: `https://ТВОЙ-АДРЕС.vercel.app`
   - **Redirect URLs**: добавить `https://ТВОЙ-АДРЕС.vercel.app/**`
     и `http://localhost:3000/**`.

**Проверка:** на боевом адресе получилось войти и загрузить фотографию.
